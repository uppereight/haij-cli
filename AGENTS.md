# haij-cli

`haij` is the command-line client and stdio MCP server for haij (app.haij.eu), the
multi-tenant form and workflow platform. It is a single static Go binary that talks to
the Rails app over `/api/v1/*` with a hand-written HTTP client. It never boots Rails and
has no database.

The server half of every endpoint lives in the private `uppereight/haij` monorepo, not
here. This repo is **public**; its history starts at v0.7.0 (2026-10-12). Earlier
history, issues and releases are in the private `uppereight/haij-cli-internal`.

## Stack

- Go, module `github.com/uppereight/haij-cli`, language version pinned in `go.mod`.
- Standard library only. No third-party dependencies, no `go.sum`.
- Pure Go: builds with `CGO_ENABLED=0`, which is also how it must be tested on a
  machine whose C toolchain is newer than the pinned Go.

## Commands

```bash
go build -o haij ./cmd/haij   # the binary
go test -count=1 ./...        # the suite (about 30 s; listencmd alone takes 16 s)
gofmt -l -s .                 # must print nothing
go vet ./...
```

CI (`.github/workflows/ci.yml`) runs gofmt, vet, build and test on every push and PR.
Nothing else is gated. There is no dev server.

## Layout

- `cmd/haij/main.go` — flag parsing and top-level dispatch. Keeps imports shallow so
  `haij --help` stays under 50 ms.
- `internal/<family>cmd/` — one package per command family (`forms`, `entries`,
  `workflows`, `webhooks`, `templates`, `contacts`, `apikeys`, `env`, `auth`, `link`,
  `doctor`, `listen`, `trigger`, `mcp`, `completion`). Each exports
  `Run(args, profile, json, stdout, stderr) int` and returns the process exit code.
- `internal/client/` — the REST client. Every endpoint path is a string literal here.
- `internal/envelope/` — the `{ok, data, summary, breadcrumbs, error}` JSON envelope
  every `--json` command emits.
- `internal/profile/` — `~/.config/haij/config.json` profiles and entitlement cache.
- `internal/mcpserve/`, `internal/mcptools/` — the JSON-RPC stdio server and its
  tool catalogue.
- `internal/catalog/` — the `haij commands --json` catalogue.
- `internal/skill/SKILL.md` — the agent-facing manual, embedded into the binary and
  printed by `haij --help --agent`.
- Add-ons: a command `main.go` does not know runs `haij-<name>` from PATH
  (`runAddon`). The plugin-building tools (`haij plugin init|validate|dev|docs|push`)
  are one: the private add-on `uppereight/haij-plugin-cli`, moved out of this repo
  (`internal/plugincmd`) on 2026-10-12 so the public CLI carries none of them while
  plugin building is internal. Do not bring them back here.
- `Formula/haij.rb` — Homebrew formula for the latest release. Generated by
  `scripts/render-formula.sh`; each release attaches a fresh `haij.rb` to commit here.
  Never hand-edit it or commit a locally rendered one (local checksums differ from CI's).
- `scripts/release.sh`, `.github/workflows/release.yml` — a `v<semver>` tag builds
  darwin/linux × arm64/amd64 archives, `SHA256SUMS` and the formula, and publishes a
  GitHub release. The repo is public, so the releases, `go install` and the Homebrew
  tap work for anyone.

## Conventions a newcomer gets wrong

- **One table here copies a Ruby constant in the Rails repo by hand** and drifts:
  the field-type list in `internal/mcptools/catalog.go` (the `type` enum of
  `haij_add_field` / `haij_update_field`) and `internal/formscmd/fields.go`
  (`FormField::FIELD_TYPES`). (The plugin tables moved to the haij-plugin add-on
  with the plugin tools.) Tests compare it with haij `origin/main` when a
  haij checkout sits beside this repo (`../haij`, or `HAIJ_REPO_DIR`; ref
  `HAIJ_REF`); without one they skip, so CI here never runs them. Run the suite
  with the sibling checkout fetched before a release. The MCP tool catalogue as a
  whole used to mirror `Haij::McpToolBuilder`; it now leads and is not kept in
  parity.
- **Tests never hit a real server.** Every command test spins up `httptest.Server`
  fixtures. A green suite does not prove the endpoint exists in Rails; check
  `config/routes.rb` in the monorepo before adding a client call.
- **Config isolation in tests and manual runs:** `HAIJ_CONFIG_HOME=<dir containing
  config.json>` overrides the profile location. Never test against the real
  `~/.config/haij/config.json`.
- **`--profile` is stripped before flag parsing** in `main.go` so it can appear anywhere
  on the line. Do not add another global flag without extending `stripGlobalProfile`.
- **`--json` after the subcommand is canonical** (`haij forms list --json`). The
  top-level parser only sees flags before the first positional, so dispatch rescans
  the tail.
- **Every catalogued command must dispatch.** `internal/catalog/catalog.go` is
  hand-maintained; a row there without a `case` in its family's `Run` ships a phantom
  command.
- **Every catalogue row is typed.** A new command or flag gets its `effect`, `args` and
  flag `type` in the same change. `TestCatalogFlagTypes` and `TestCatalogEffects` check
  them against the parsers and `internal/client`.
- **Errors from non-JSON responses** (a Rails 404 or 500 page) never reach the user
  raw: `internal/client` turns them into code `http_<status>` and a message with the
  method, path and status, and drops the body (`nonJSONErrorMessage`, #4). Keep it so.

## Off-limits

- Do not add dependencies without a reason that survives review. The zero-dependency
  build is deliberate.
- Do not commit anything under `.workbench-local/` or `.workbench-context/`.
- No Claude or AI attribution lines in commits or PRs.
